# 投标团队最苦的活，我们用 AI Agent 重做了一遍

> 从一份招标 Excel 到逐条作答、证据引用、人工审核与结果回填：一个投标Agent案例，和它背后的 Agent 工程方法。

做过投标的人都知道，最消耗人的环节，往往不是写一段漂亮的方案介绍，而是逐条核对客户的技术要求。

客户发来一份招标文件，Excel 摊开几百行。每一行都在问：你们的产品能不能做到？支持哪些标准？有没有对应资质？能不能满足交付条件？

投标团队需要做的，不只是回答“满足”或“不满足”，而是，每一个判断都要有依据。

它可能来自产品规格书的某一页、芯片手册的一张表、历史项目的一段说明，或者一份资质文件里的某个条款。  
如果找不到证据，就不能轻易下结论；如果答错一条，可能影响客户评分；如果漏掉一条，可能直接埋下投标风险。

所以，一份标书，几个人对着啃三五天并不稀奇。真正有价值的判断经验，也往往压在少数资深员工身上：新人很难接住，老师傅一忙，整个流程就会变成瓶颈。

我们最近和一家全球领先的智慧家庭设备厂商一起，把这件事交给了一个**投标Agent**。

![alt text](./images/1.jpg)


它不是简单“帮忙写答案”，而是把投标应答中最重复、最耗时、最容易出错的一段流程，重新整理成了一条可验证、可追溯、可持续迭代的智能工作流。


---

## 一份空白标书进去，一份带依据的答复出来

这个投标Agent要做的事情，可以用一句话概括：

**上传一份招标 Excel，投标Agent逐条对照企业知识库，判断“满足 / 不满足”，附上引用依据，并在人工审核后回填成标准标书。**

它背后的流程大致分为五步：

1. **上传**:把客户的 Excel 标书模板传进系统。
2. **解析**:系统自动认出哪些列是题号、题干、答复栏,从几百行里抽取出真正需要回答的需求清单。
3. **应答**:投标 Agent 逐条对照企业知识库,判断"满足 / 不满足",并附上引用依据。
4. **追问**:信息不够时,Agent 不会瞎编,而是主动向人提问。
5. **导出**:人工审核后一键回填成标准 Excel,可直接交付。

![alt text](./images/2.jpg)

在这个过程中，人的角色发生了变化。

过去是“人逐条找资料、逐条判断、逐条填写”。  
现在是“AI 先出答卷，人来审结论、补判断、控风险”。

这不是让 AI 替代投标人员，而是让 AI 接住重复劳动，把人留给真正需要经验的判断。

## 这个 Agent 为什么不能只是“会聊天”？

投标答标不是普通问答。

在智能终端、机顶盒、Android TV 等领域，标书里会出现大量硬核技术要求：主控芯片、视频编解码、DVB / IP、安全启动、4K HDR、Dolby、Launcher、宽带网关、运营商定制能力……

这些问题不能靠模型“常识”回答。

“通常支持”“一般可以”“大多数产品具备”这类表述，在销售和合规场景里都是高风险词。  
真正可用的投标Agent，必须做到四件事：

### 1. 答必有据

每一条判断都必须带引用依据。  
Agent 需要说明自己检索了什么关键词、找到了哪段原文、出自哪份文档、哪一页或哪一行。

### 2. 不确定就追问

知识库里没有足够信息时，Agent 不能编。  
它要明确标记“证据不足”，并把问题抛给人工。

### 3. 全程可审计

每一次检索、判断、引用和修改都要被记录。  
这样，后续复盘时才能知道：为什么这条答成“满足”？依据是什么？谁改过？

### 4. 能持续变准

人工审核不是流程的终点，而是下一轮优化的起点。  
被纠正的答案、补充的资料和新增的判断规则，需要沉淀下来，成为之后的训练与评测数据。

## 四块能力，块块能单独演示

为了让这套系统既能完整跑通，也方便逐步落地，我们把投标Agent拆成了四块核心能力。

### ① 标书解析

不靠死板模板。  
由大模型识别 Excel 的列角色，自动把内容分成“标题 / 说明 / 真实要求”三类，只把需要回答的挑出来。

即便遇到格式奇怪的模板，列识别异常时也会自动回退到关键词检测，保证流程不卡壳。

### ② 知识库管理

产品规格书、芯片手册、资质文件、过往案例等 PDF / Word 文档，经解析转成结构化内容入库，并能按任务绑定相关子集。

原始文件全程可追溯，Agent 必要时能直接调出原图核对。

### ③ 智能应答

Agent 像一个细致的工程师那样工作：检索知识库、读上下文、给出判断。

每一个答案都带引用（来源文件、行号、原文摘录），可追溯、可复核。  
支持多种大模型按需切换，前端实时显示处理进度，不是一个看不见过程的“黑箱”。

### ④ 追问与导出

信息不足时，Agent 自动发起追问。  
人工补充后，系统继续完成剩余任务。

审核完成后，答案可以批量导出，并回填到原始 Excel 模板中，保证交付格式不变。

## 准确率不是“测一次”，而是做成持续回归

企业级 Agent 最怕的是：Demo 看起来很好，上线后却无法稳定复现。

因此，这个项目从一开始就没有把“准确率”当成一次性验收数字，而是做成了一套持续回归机制。

我们先从真实标书中构建金标数据集，由业务专家给出标准答案与标准引用；再把每次模型、提示词、知识库或检索策略的改动，都放进同一套评测中重新跑一遍。

随着工程迭代，整体准确率从 **75.7%** 提升到 **84.9%**，最终达到 **92.5%**。

![alt text](./images/4.jpg)

这组数字背后，不只是“换了一个更强的模型”。

真正起作用的，是一整套工程细节：

- 标书列角色识别与异常回退
- 文档解析与切分策略优化
- 检索关键词与召回范围调整
- 多轮上下文拼接
- 引用约束与答案格式校验
- 人工纠错数据回流
- 不同模型之间的对比评测

换句话说，Agent 的能力不是“训练完就结束”，而是需要被持续评估、验证、发布和回退。

## 我们用“4+2”指标，不只看答案对不对

只看最终答案是否正确，无法解释一个 Agent 为什么出错。

因此，我们把评测拆成了“4 个核心指标 + 2 个进阶指标”。

![alt text](./images/5.jpg)

四个核心指标分别关注：

- **需求识别准确率**：该回答的行有没有被正确抽取出来
- **结论准确率**：满足 / 不满足的判断是否正确
- **引用准确率**：引用是否真的支撑结论
- **格式完整率**：输出是否满足标书格式要求

两个进阶指标进一步关注：

- **追问有效率**：信息不足时，Agent 是否提出了真正有用的问题
- **人工修改率**：最终交付前，有多少内容需要人工重写

这种拆分方式的价值在于，一旦结果变差，我们能快速定位问题究竟出在解析、检索、推理、引用还是格式环节。

## 企业级 Agent，难点从来不只是模型

这个投标Agent项目给我们最深的感受是：

**真正决定企业级 Agent 能不能落地的，往往不是模型“会不会答”，而是整个系统能不能被验证、被追踪、被纠正、被持续迭代。**

在投标场景里，模型只是其中一环。

前面有文档解析、知识库建设和检索；中间有推理、引用和追问；后面还有人工审核、Excel 回填、评测体系和版本管理。

只有这些环节一起形成闭环，Agent 才能从一个“看起来聪明的 Demo”，变成真正能进入业务流程的生产系统。

我们也在这个过程中逐渐形成了一套更通用的 Agent 工程方法：

- 用真实业务数据构建金标集
- 用可观测链路记录每一步决策
- 用回归测试控制每次迭代风险
- 用人工反馈推动系统持续变准
- 用模块化能力支持分阶段落地

这套方法不只适用于投标。

采购询价、合同审核、售前问答、合规检查、客服知识应答等场景，本质上都面临相似的问题：**信息分散、判断要求高、结果必须有依据、错误成本不能忽略。**

---

## 结语

过去，投标团队最苦的活，是在几百行 Excel 和几十份资料之间来回翻找。

现在，Agent 可以先完成检索、判断、引用和回填，人只需要把精力放在关键审核与业务决策上。

这不是让 AI 替人写标书。

而是把一段高度重复、却又要求严谨的工作，重新设计成了一条可验证、可追溯、可持续进化的智能流程。

这，才是企业级 Agent 真正值得落地的地方。
